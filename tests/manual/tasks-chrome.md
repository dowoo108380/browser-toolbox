# 정식 Chrome에서 작업 결과 알림 확인(시험 빌드)

작업 결과 알림(COM-10, 결정 0024)은 실행 기능이 있어야 볼 수 있는데 제품에는 아직 실행 기능이 없다. 그래서 시험 기능("시험 작업", "다른 시험 작업")을 넣은 시험 빌드(결정 0025)를 정식 Chrome에 올려 본다. 확장 전체 시험(`tests/e2e/tasks.spec.ts`)은 팝업 문서를 탭으로 열어 보므로, 실제 팝업을 닫는 것, 배지의 모양과 아이콘 제목, 전체 화면 위의 알림은 여기서 본다. 첫 실행 기능(SUB-1 등)을 만들면 그 기능의 절차로 옮긴다.

## 준비

- `pnpm verify`를 통과한 상태에서 `pnpm build:fixture`로 만든 `dist-fixture/`
- Windows의 Chrome 최신 안정판
- 제품 빌드(`dist/`)를 올려 두었으면 `chrome://extensions`에서 잠시 끈다. 둘이 함께 켜져 있으면 콘텐츠 스크립트가 둘씩 돈다. 시험 빌드는 폴더가 달라 확장 id와 설정이 따로다.
- 서비스 워커의 개발자 도구 창은 페이지 창을 덮지 않게 나란히 둔다. 페이지가 가려지면 Chrome이 문서를 보이지 않는 것으로 보아 페이지 위 알림을 띄우지 않을 수 있다(그때는 배지만 남는 것이 맞다).
- 시험 작업의 일은 끝을 쓸 때까지 기다린다. 아래 한 줄을 서비스 워커 개발자 도구의 콘솔에 붙여 넣는다(`outcome`은 `'succeed'`, `'fail'`, `'cancel'`, `featureId`는 `'fixture-task'` 또는 `'fixture-other'`). 일은 20초가 지나면 시간 초과로 끝난다.

```js
chrome.storage.session.set({
  'fixture-task:release': { featureId: 'fixture-task', outcome: 'succeed', serial: Date.now() },
});
```

## 절차

1. `chrome://extensions`에서 "압축 해제된 확장 프로그램을 로드합니다"로 `dist-fixture/`를 고른다. 카드의 "서비스 워커"를 눌러 개발자 도구를 연다.
   - 기대: 오류가 없다.
2. 아무 http·https 페이지를 연다. 그 탭을 보는 채로 확장 아이콘을 눌러 팝업을 열고, "탭" 범주의 "시험 작업"을 누른 뒤 페이지를 눌러 팝업을 닫는다.
   - 기대(COM-10.3): 누르면 팝업 위쪽에 "시험 작업: 진행 중이다."가 보이고, "다른 시험 작업"에 "쓸 수 없음: 이 탭에서 시험 작업 진행 중"이 보인다(COM-10.7).
3. 서비스 워커 콘솔에서 `succeed`로 끝을 쓴다(그 창의 지금 탭이 그 페이지인 채로).
   - 기대(COM-10.1): 그 탭의 확장 아이콘에 초록 바탕의 흰 ✓ 배지가 보인다. 아이콘에 마우스를 올리면 "Browser Toolbox: 시험 작업 끝남"이 보인다.
   - 기대(COM-10.1): 페이지 오른쪽 위에 "시험 작업: 끝났다. 시험 결과"가 3초쯤 보였다 사라진다. 글이 잘리지 않고 읽기 쉽다. 알림이 떠 있는 동안에도 그 아래의 페이지를 누를 수 있다.
4. 다른 탭으로 옮겼다가 돌아온다. 그 페이지에서 링크를 누르거나 새로 고친다.
   - 기대(COM-10.5): 다른 탭의 아이콘에는 배지가 없다. 돌아오면 ✓가 그대로다.
   - 기대(결정 0024): 다른 페이지로 이동하거나 새로 고쳐도 ✓와 제목이 남는다.
5. 그 탭에서 팝업을 연다.
   - 기대(COM-10.4): 위쪽에 "시험 작업: 끝났다. 시험 결과"가 보이고, 아이콘의 배지가 사라진다. 팝업을 닫았다 다시 열면 결과가 없다.
6. 팝업을 열고 팝업 안에서 오른쪽 단추로 "검사"를 눌러 팝업의 개발자 도구를 연다(검사하는 동안 팝업은 초점을 잃어도 닫히지 않는다). 팝업에서 "시험 작업"을 누르고, 팝업의 개발자 도구 콘솔에서 `succeed`로 끝을 쓴다(팝업에서도 같은 한 줄이 된다).
   - 기대(결정 0024): 팝업에 결과가 보이고, 페이지 위 알림은 뜨지 않으며, 배지는 남지 않는다.
   - 확인한 뒤 팝업의 개발자 도구를 닫는다.
7. 팝업에서 "시험 작업"을 누르고 닫은 뒤 `fail`로 끝을 쓴다.
   - 기대(COM-10.2): 빨간 바탕의 흰 ! 배지, 제목 "Browser Toolbox: 시험 작업 실패", 페이지 위 "시험 작업: 실패했다. 시험 작업이 실패했다.", 다시 연 팝업에도 같은 글.
8. 영상이 있는 페이지에서 팝업으로 "시험 작업"을 누르고 닫은 뒤, 서비스 워커 콘솔에 아래 한 줄(5초 뒤에 끝을 씀)을 넣는다. 곧바로 그 페이지로 돌아가 영상을 전체 화면으로 한다.

   ```js
   setTimeout(
     () =>
       chrome.storage.session.set({
         'fixture-task:release': {
           featureId: 'fixture-task',
           outcome: 'succeed',
           serial: Date.now(),
         },
       }),
     5000,
   );
   ```

   - 기대(결정 0018, 0024): 5초 뒤 전체 화면 위에 알림이 보인다(나중에 띄운 것이 최상위 층의 위에 그려진다).

9. 다른 탭(페이지 B)을 앞에 둔 채 페이지 A에서 시작한 작업의 끝을 쓴다(A에서 팝업으로 시작하고 닫은 뒤 B로 옮김).
   - 기대(결정 0024): B에는 알림이 뜨지 않는다. A로 돌아가면 알림은 없고 배지만 있다.
10. 진행 중인 탭을 닫는다(팝업에서 시작하고 닫은 뒤 그 탭을 닫음). 서비스 워커 콘솔에서 `chrome.storage.session.get('tasks')`를 본다.
    - 기대(COM-10.6): 닫은 탭의 기록이 없다.
11. 확인을 마치면 시험 빌드를 확장 목록에서 지우고(카드의 "삭제") 제품 빌드를 다시 켠다.

## 기록

확인한 날짜, Chrome 버전, 빌드(커밋), 각 단계의 결과와 다른 점을 `docs/history.md`의 맨 아래에 더한다.
