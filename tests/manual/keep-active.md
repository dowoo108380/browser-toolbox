# 페이지 활성 상태 유지(TAB-2) 확인

자동 시험(`tests/e2e/keep-active.spec.ts`, `keep-active-long.spec.ts`)은 화면 없는 Chromium에서 탭 바꾸기, 최소화, 분할 보기, 다른 페이지로 이동, 전체 화면 요청이 창 전체가 되는지(창의 상태), 타이머, 가짜 입력을 본다. 그 브라우저에서 만들 수 없거나 볼 수 없는 것을 이 절차로 정식 Chrome에서 본다: 화면에 보이는 진짜 전체 화면과 NVIDIA RTX Video, 다른 프로그램을 쓰는 동안(TAB-2.17), 다른 창에 가려진 창(TAB-2.18), 디버깅 안내 막대의 취소(TAB-2.7), 안내 막대를 숨기는 옵션, 개발자 도구를 연 탭, 실제로 쓰는 사이트(결정 0041).

## 준비

- `pnpm verify`를 통과한 빌드(`dist/`)를 정식 Chrome에 올린다(`tests/manual/smoke-chrome.md`의 1–2단계). 이미 올려 두었으면 `chrome://extensions`에서 그 확장의 다시 불러오기(↻)를 누른다.
- 탭을 넷 연다: (가) 평소 보는 영상 사이트의 긴 영상(예: YouTube), (나) 평소 쓰는 강의 사이트처럼 다른 사이트의 재생기를 페이지 안에 넣은 곳(없으면 다른 사이트의 영상을 넣은 아무 글), (다) 아무 웹 페이지, (라) `chrome://discards`.
- NVIDIA RTX Video를 쓰면: NVIDIA 제어판의 "비디오 이미지 설정 조정" → "RTX 비디오 향상"을 켜 둔다. 그 화면에 영상이 재생되는 동안 상태(활성)가 보이는 판이면 그것으로 보고, 없으면 화질 차이로 본다(추측: 판마다 보이는 곳이 다를 수 있다).
- 다른 프로그램 하나(메모장)를 준비한다.
- 3·5단계는 개발자 도구의 콘솔에 아래 한 줄을 붙여 넣어 본다. 페이지가 보는 초점과 보임, 창의 초점 신호를 2초마다 적는다(페이지가 직접 거는 것과 같은 자리에서 듣는다). 콘솔 위 문맥 고르기에서 iframe을 고르고 한 번 더 붙여 넣으면 그 iframe도 적는다.

  ```js
  addEventListener('blur', (e) => e.target === window && console.log('창 blur'));
  addEventListener('focus', (e) => e.target === window && console.log('창 focus'));
  document.addEventListener('visibilitychange', () =>
    console.log('보임 바뀜', document.visibilityState),
  );
  setInterval(() => console.log(document.hasFocus(), document.visibilityState), 2000);
  ```

## 절차

1. (가) 탭을 보는 채로 팝업을 열고 "탭" 범주를 고른다. "페이지 활성 상태 유지"의 "이 창의 탭"에서 (가)와 (나)를 고르고 "고른 탭 켜기"를 누른다.
   - 기대(TAB-2.19, TAB-2.24): 두 탭이 "켜짐"이고 (라)는 "꺼짐 · 쓸 수 없음: 웹 페이지에서만 쓸 수 있음"이다. 확장 아이콘의 배지와 제목은 그대로다. (가)는 보는 탭이라 안내 막대가 없다. (나)는 뒤에 있으므로 Chrome이 창 위에 디버깅 안내 막대를 띄운다(기대 동작 12).
   - (라) `chrome://discards`의 표에서 (가)와 (나)의 "Auto Discardable"이 꺼짐(✗)이다(TAB-2.21).
2. **전체 화면과 RTX Video**(TAB-2.16). (가)에서 영상을 재생하고 전체 화면(영상의 전체 화면 단추 또는 F)으로 한다.
   - 기대: 영상이 모니터 전체를 채운다(탭 안이나 창 안에서만 커지지 않는다). RTX Video를 쓰면 상태가 활성이다(또는 꺼 둔 때보다 선명하다). 전체 화면을 끝낸다.
3. **보지 않는 탭**(TAB-2.1, TAB-2.2). (가)에서 영상이 재생되는 채로 (다)로 가서 1분 기다린 뒤 (가)로 돌아온다. 이어서 창을 최소화해 1분 기다린 뒤 되살린다. (가)에서 개발자 도구를 열고 준비의 한 줄을 붙여 넣은 뒤 하면 그동안의 기록이 남는다.
   - 기대: 그동안 영상이 멈추지 않는다(돌아오면 그만큼 진행했다). 콘솔의 2초 기록이 끊기지 않고 `true visible`이며 "창 blur"·"보임 바뀜"이 없다. 돌아오면 (나) 때문에 안내 막대는 남는다.
   - 다시 전체 화면으로 한다. 2단계와 같이 모니터 전체를 채우고 RTX Video가 활성이다(TAB-2.16 "다른 탭으로 갔다가 돌아온 뒤에도").
4. (나)를 보는 탭으로 하고 영상을 재생한 뒤 (다)로 가서 1분 기다리고 돌아온다.
   - 기대: 다른 사이트의 재생기 안 영상도 멈추지 않는다. 강의 사이트가 "자리 비움"이나 "다른 창을 보고 있음"으로 멈추는 곳이면 그 알림이 나오지 않는다.
5. **다른 프로그램을 쓰는 동안**(TAB-2.17). (가)를 보는 채로 콘솔(준비의 한 줄)을 켜 두고, Chrome 창 옆에 메모장을 놓아 메모장을 누르고 1분 쓴다. 콘솔 위 문맥 고르기에서 (나)의 재생기 iframe을 골라도 본다((나)를 보는 채로 같은 일을 한다).
   - 기대: Chrome 창이 초점을 잃어도 2초 기록이 `true visible`이고 "창 blur"가 없다(최상위와 다른 사이트의 iframe 모두). 메모장에서 Chrome으로 돌아와도 "창 focus"가 없다(페이지는 초점을 잃은 적이 없다). 입력란을 눌렀다 떼는 것 같은 페이지 안의 초점 바뀜은 평소와 같다.
   - 비교: 팝업에서 (가)를 골라 "고른 탭 끄기"를 누른 뒤 같은 일을 하면 `false visible`과 "창 blur"가 찍힌다. 다시 켠다.
6. **가려진 창**(TAB-2.18, 기대 동작 3). (가)를 보는 채로 영상을 재생하고 메모장을 최대화해 Chrome 창을 완전히 덮은 채 1분 둔다. 그다음 Chrome 창을 누른다.
   - 기대: 덮인 동안 영상이 멈추지 않고 콘솔 기록이 끊기지 않는다(`true visible`). 덮은 지 1초쯤 뒤 디버거가 붙는다(Chrome 창을 누르면 안내 막대가 보이다가 1–2초 안에 사라진다. (나)를 꺼 두면 잘 보인다). Chrome 창을 누른 뒤 전체 화면이 2단계처럼 모니터 전체다.
   - 한계(사용자가 고름): 메모장을 치우기만 하고 Chrome 창을 누르지 않으면 디버거가 붙은 채이고, 그동안 전체 화면이 탭 안에서만 되고 RTX Video가 꺼진다. 누르면 돌아온다.
7. **개발자 도구를 연 탭**(기대 동작 9의 2026-10-21 확인). (다)를 켜고 (다)에서 개발자 도구(F12)를 연 채 (가)로 간다.
   - 기대: (다)가 "켜짐" 그대로이고 이유가 보이지 않는다(지금의 Chrome은 개발자 도구와 함께 붙는다). (다)로 돌아와 개발자 도구를 닫는다.
8. **안내 막대의 취소**(TAB-2.7). (나)가 뒤에 있어 안내 막대가 보이는 채로 막대의 "취소"를 누른다. 팝업을 연다.
   - 기대: 켜져 있던 탭이 모두 "꺼짐 · 디버깅 안내 막대에서 취소해 껐다. 다시 켜면 다시 붙인다."이고 "모든 탭" 스위치가 꺼짐이다. 탭을 오가도 막대가 다시 뜨지 않는다. `chrome://discards`의 "Auto Discardable"이 원래(✓)로 돌아온다(TAB-2.21).
   - (가)와 (나)를 다시 켜면 (나)가 뒤에 있으므로 막대가 다시 뜬다.
9. **안내 막대를 숨기는 옵션**(기대 동작 12). Chrome 창을 모두 닫고(작업 표시줄에 남은 Chrome도 끝낸다), README "쓰는 법"대로 바로 가기의 "대상"에 `--silent-debugger-extension-api`를 붙인 바로 가기로 Chrome을 켠다. (가)와 (나)를 켜고 (나)를 뒤에 둔다.
   - 기대: 안내 막대가 뜨지 않는다. 3단계처럼 (나)의 영상이 멈추지 않는다.
   - 그 바로 가기가 아닌 보통의 방법으로 Chrome을 다시 켜면 막대가 다시 뜬다. 옵션의 보안 주의는 README에 있다(그 바로 가기로 켠 동안에는 디버거 권한이 있는 다른 확장도 알림 없이 디버거를 쓸 수 있다). 확인한 뒤 바로 가기를 원래대로 돌릴지는 사용자가 정한다.
10. **실제로 쓰는 사이트**(TAB-2.9, TAB-2.10, 남은 위험 N-04). 자리 비움으로 로그아웃되거나 멈추는 사이트를 쓰면, 그 탭을 켜고 그 사이트의 기준 시간보다 오래 뒤에 둔다(최소화나 다른 탭).
    - 기대: 돌아왔을 때 로그아웃되거나 멈춰 있지 않다. 그 사이 페이지의 메뉴가 열리거나 무엇이 눌린 흔적이 없다(가짜 입력은 안전한 곳의 마우스 움직임뿐이다). 서버가 시간이 지나 세션을 끊는 것은 막지 못한다(기대 동작 7).

## 알릴 것

- 기대와 다른 단계의 번호와 본 것. 화면이나 콘솔의 글은 주소, 제목, 계정이 보이지 않게 가리고 보낸다.
- 2·3·6단계에서 RTX Video의 상태를 볼 수 없었으면 그렇다고 적는다(화질로만 봤는지).
- 10단계에서 막지 못한 사이트가 있으면 그 사이트가 무엇으로 자리 비움을 판단하는지(마우스, 키보드, 초점) 아는 만큼. 사이트의 화면 구조를 볼 때는 구조만 보는 방법으로 한다.
